# Retail 12.1.0 bag and bank audit

Date: 2026-09-09. Scope: `BagsStore`, `BankStore`, `BagsWindow`, `BankWindow`, `BagsBridge`, and shared `ContainerItemSupport`, with currency configuration and locale integration checked. The follow-up combat-opening fix is included below; the user confirmed it works in-game before release 7.5.0.

## Findings and implemented changes

| Priority | Finding | Result |
| --- | --- | --- |
| High | Gems were classified as trade goods/reagents or Past Expansions; item-enhancement class items could fall into Miscellaneous. | Added **Enhancements** for `Enum.ItemClass.Gem`, `ItemEnhancement`, and Consumable / `ItemConsumableSubclass.Itemenhancement`. This rule runs before expansion, quest, and reagent rules, so old gems and temporary/permanent enchants are included. Enchanting dust, shards, and recipes retain their material/recipe categories. |
| High | Banks duplicated an older classifier with no Season or Past Expansions support. | Banks now delegate classification, metadata resolution, category labels, and ordering to BagsStore. The same item follows the same base category in all three stores. |
| High | Neither store handled delayed item-data completion. A first scan could permanently retain fallback names, incomplete tooltip search, or the wrong category until another bag event. | Deduplicate missing-data requests by item ID, retain every affected bag ID, handle `ITEM_DATA_LOAD_RESULT`, invalidate partial tooltip metadata, and queue a consolidated refresh. Closed banks are never scanned from the callback. Failed loads do not enter an automatic retry loop; a later ordinary scan may request again. |
| High | The metadata cache was keyed only by item ID. Different bonus/scaled links could inherit the other variant's description and level, especially during offline recategorization. | Build independent metadata records, clear instance-dependent fields on link changes, persist class/subclass/required level in slot records, and prefer slot data during migration. Snapshot comparisons include the new fields. Valid API minimum level takes priority over English tooltip parsing. |
| Medium | Any English Hero/Veteran/etc. upgrade-track text could mark old level-80 equipment as current seasonal dungeon gear. | Upgrade-track fallback applies only when required level is unknown. A known level below the current expansion maximum stays in Past Expansions; level-90 loot from returning dungeons stays Equipment. |
| Medium | `root and CommitDirtyView(...) or nil` converted a successful unchanged Warband scan (`false`) into a failed scan (`nil`). | Preserve the return value. Only a missing/incompatible view triggers the full-rescan fallback. |
| Medium | `CanUseBankType` returned true if the API was absent or errored. | Failure returns false, preserving cached snapshots and disabling live interactions until access is confirmed. |
| Medium | Bank tab/settings and item-data events relied on a later `BAG_UPDATE_DELAYED` that need not occur. | Register `BANK_TABS_CHANGED`; queue and coalesce pending commits for tab/settings, container, legacy slot notifications, and item data. Existing dirty/full-scan checks suppress duplicate work. |
| Medium | Each scan broadcasts three notifications, and each notification synchronously rebuilt the entire visible window. | Coalesce data notifications into one deferred layout per window. Currency notifications join the bag queue. Hidden/disabled windows skip queued work. This is a reduction in layout calls, not a measured FPS claim. |
| Medium | Ordinary carried-bag updates rebuilt account totals from every saved character. | Reuse the existing aggregate-delta helpers to replace only the current character's contribution. Fall back to a full rebuild if the existing index is inconsistent. Full inventory scans still rebuild the index. |
| Medium | Saved alt/bank categories would otherwise retain the old rules. | Bags schema 7 rebuilds carried categories/account indexes. Bank category version 1 migrates character and Warband snapshots without changing their last-seen timestamps or item counts. |

The existing New Items overlay still temporarily presents newly acquired carried items in New Items. Cleanup/expiry returns them to their base category, including Enhancements. Category collapse/layout preferences remain keyed by their existing IDs; the new category starts with its default layout. English provides the fallback label for locales without a translation.

Blizzard's [September hotfix article](https://worldofwarcraft.blizzard.com/en-us/news/24296142) documents the current Spark of Tides/Tidal Spark Dust reward fixes and Trovehunter's Bounty quest interactions. The [WoWDB item row](https://www.wowdb.com/items/274476-spark-of-tides) exposes the client item ID and Midnight Season 2 label; its [Adventurer Mistcrest row](https://www.wowdb.com/currencies/3442-adventurer-mistcrest) confirms the existing Season 2 currency family. These are game-data references; no seasonal IDs were inferred from names alone.

The classifier is intentionally not a comprehensive season-expiry database. Previous-season items within Midnight may still appear in Season. Quest-starting seasonal items keep Quest priority, and arbitrary new tokens need a verified ID/rule. Adding all tooltip text containing “season” would incorrectly capture equipment and unrelated items.

The patch also converts old housing dyes/pigments from bags and banks through mail. This addon should record the resulting inventory through ordinary scans, not invent a conversion or delete saved records. Offline bank snapshots remain last-seen data until the bank is visited. See Blizzard's [12.1 housing update](https://worldofwarcraft.blizzard.com/en-us/news/24295382/).

## API and interaction review

- `C_Item.GetItemInfo` can return no data; its expansion, class/subclass, minimum-level, and reagent fields now feed both stores. `RequestLoadItemDataByID` / `ITEM_DATA_LOAD_RESULT` provide the refresh path. Source: Blizzard [item API definitions](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ItemDocumentation.lua).
- Bank access, auto-deposit, item admission, and tab events are represented by the current `C_Bank` namespace. `BANK_TABS_CHANGED` carries the bank type and now uses the existing per-type invalidation path. Source: Blizzard [bank API definitions](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/BankDocumentation.lua).
- Carried bags use the enumerated backpack, four regular bags, and reagent bag; bank scanning uses the existing character/Warband enum lists. Snapshot replacement still requires live access. No legacy negative bank-container IDs were added.
- Warbound deposit still checks combat state, live Warband access, and API availability. The addon already avoids changing Blizzard's selected bank tab from insecure code because of the documented local taint history.
- Shared native container overlays, modified-click linking, stack splitting, and combined-stack targeting remain the interaction layer. Secure fallback buttons are retained for bank/default callers, but carried bags now explicitly opt out. The standalone suite does not simulate WoW's secure execution or cursor behavior.

API references above use the moving `live` source mirror as inspected on the audit date. They are not a claim that Mechanic's offline database or every reference is pinned to the installed client's exact build. Mechanic's deprecation scan explicitly reported its fallback database.

## Combat-opening follow-up

The supplied in-game error confirms `ShowWindow → RefreshWindow → HideAllReusableFrames → Frame:Hide()` is blocked. The shared factory created a `SecureActionButtonTemplate` child for every carried item, even when the native overlay handled interaction and the secure fallback was hidden. That child protects its ancestors, including the item button being hidden by the layout.

Implemented:

- Carried item buttons opt out of secure fallback construction. Hiding or disabling an already-created secure child would not remove this problem; a reload is required to construct the new frame tree.
- The native overlay now checks actual frame protection before deferring updates. Unprotected carried item buttons can be created, hidden, shown, and reassigned to live bag/slot targets in combat.
- Bag IDs go through Blizzard's `SetBagID` attribute-backed setter, rather than an addon-owned parent ID. The original native `OnClick` remains attached; addon code does not invoke the protected item-use API.
- Combined consumables use the same native overlay and resolve an unlocked constituent slot. Previously, combined records lacked direct bag/slot fields and depended on the secure fallback.
- Switching a reused button to an offline item hides and disables its old live overlay, including in combat. Protected bank/default callers retain their existing secure fallback and defer native-overlay updates before mutation.

Blizzard's [container XML](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/ContainerFrame.xml) defines the native item template, and its [container implementation](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/ContainerFrame.lua) shows the original click handler, item-location callback, and attribute-backed bag-ID setter. Native bag item use still follows the game's item restrictions and cooldowns; this change does not make out-of-combat-only items usable in combat.

`lua tests/bags_combat_spec.lua` runs the 78 existing checks plus **24 combat regression checks**. Its frame model reproduces the protected-child Hide failure, then verifies carried construction in combat, the actual show/refresh/hide/close/toggle path, preserved native handlers, combined-stack targets, target changes after reuse, offline input suppression, and protected-caller deferral. It tests addon logic, not WoW's secure execution engine.

The user confirmed the combat fix works in-game on 2026-09-09. The detailed regression checklist for future changes is: open bags for the first time while fighting a training dummy; close/reopen with the bag key and close button; right-click a combat-usable consumable in individual and combined views; consume the final item in a stack and verify the next target; then repeat after combat. Check for new blocked-action or taint reports. Bank combat opening and changing Escape overrides during combat are separate existing paths, not claimed as fixed here.

Other remaining performance opportunities require profiling: category retrieval scans slots once per visible category; tooltip cache alternation between multiple links of one base ID can still repeat work; item-level display still resolves detailed levels during layout. These were not expanded into unrelated rewrites during this pass.
